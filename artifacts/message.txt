Record what became of the run's own :review entry

The `:review` ledger entry is the review loop's memory: the next run on the
branch reads its open list, its standing needs and the design verdict filed
beside it. When an append was refused, the loop said so on the stderr of
whoever ran it, which the run dir does not keep — so every durable artifact
of a run whose entry never landed was identical to one whose did, while the
next run silently inherited the open list of the run BEFORE it
(`prior-open`'s one-hop bound reads the latest `:review` ENTRY, so a skipped
run makes it two hops). Three analyses reconstructed that by evaluating the
ledger's own checks by hand; one run's verdict, which had found three
invariant breaches no reviewer raised, was lost with it.

`append-review-entry!` now answers what happened, and the report carries it
beside `design-verdict.ledger`, where the verdict's own outcome has been
since a refusal cost a pass nobody could diagnose. The analysis payload
carries it too, so a run the workstream does not hold is titled `not
recorded` rather than graded on counts nothing downstream will read.

The `Deviation:` stamp gets the same treatment. It rewrites a commit on the
reviewed branch — the one place an analysis may not go and look — and its
only account was a println. What was owed is recorded beside what was
stamped, because the stamp is best-effort per layer and a partial one shows
nowhere else.

The refusal these analyses were written about is already gone: 57d48717 let
a record inherit the goals it cites, and both wedged workstreams have
written a `:review` and a `:design-verdict` since. What was left is that
nothing durable said which of the two had happened.

The tail write persists only over a report the run itself wrote. Minting one
would hand `analysis/enqueue!`'s report gate a report of a run that did
nothing, which is the case that gate exists to refuse.
